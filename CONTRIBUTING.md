# Community contributions / Вклад сообщества

Game Assist расширяется через **декларативные проверяемые данные**, а не запуск
произвольных community plugins. Универсальны регистрация AppID, разрешения,
наблюдения и неизвестное состояние; конкретные игровые факты универсальными
не становятся. Новый профиль не читает приватный аккаунт и не включает парсер.

## Два независимых типа вклада

1. **Профиль игры** — `knowledge/game_profiles.json`, схема
   `knowledge/profile_schema.json`, модели `knowledge/profiles.py`.
   Это личность игры и проверенное покрытие конкретной версии/формата.
2. **База прохождения** — `knowledge/catalog.json`, схема
   `knowledge/schema.json`. Места/требования, source attribution, права, отдельный
   review сопоставления флагов и отдельный spoiler-safe hint review.

`profiles/*.json` — старые identity-only файлы, не новый approved registry.
Не используйте их старые описания возможностей как доказательство parser coverage.

## Процесс: источник → review → тесты → approved registry

- Создайте draft записи с реальным Steam AppID, собственным описанием и ссылками
  на первичные источники. Не угадывайте game build, флаги или проценты покрытия.
  `unknown` — нормальный результат. Неизвестный AppID не запрещает добавить игру
  в аккаунт; он лишь не получает проверенных игровых возможностей из реестра.
- Зафиксируйте provenance, права/лицензию и точную ревизию источника парсера
  (`sha256:` локально проверенного исходника), не исполняемый путь, shell-команду
  или URL установки. Source URL — справочная ссылка: загрузчик её не открывает.
- Для каждого verified capability нужны отдельные ссылки на review исходника,
  синтетические тесты и обезличенный отчёт о разрешённой private fixture проверке.
  Не прикладывайте настоящий сейв, SteamID, токен, персональный путь или значения
  личного прогресса в issues, PR, fixtures или screenshots.
- Указывайте точный `game_version`. Для ограниченного `resource_scalars` можно
  установить только `save_format_version` и оставить game version неизвестной;
  это **не** утверждение совместимости со всеми сборками игры. Wildcard и диапазоны
  версий запрещены. После обновления игры неизвестное остаётся неизвестным.
- Reviewer проверяет смысл каждого поля, источник и права; текст `verified` сам по
  себе не доказательство. Другой review отдельно проверяет spoiler-safe поведение.
- Запустите проверки ниже. На PR покажите результат и не прячьте неисполненные
  проверки. Только maintainer после review переводит запись из `draft` в
  `approved` и включает её в поставляемый registry. Публичный PR/репозиторий здесь
  пока не создан; этот процесс подготовлен для будущей публикации.
- Новый код декодера — отдельный обычный code-review PR с угрозами, ограничениями
  read-only worker и тестами. Профиль никогда не динамически импортирует Python,
  не скачивает/не запускает программы и не разрешает приватный доступ.

## Права и лицензии

MIT относится к оригинальному коду Game Assist, не ко всем данным об играх.
Лицензия собственных manifest-описаний указана явно; общественная база прохождения
требует отдельного согласованного решения о лицензии. Не копируйте чужие гайды,
карты, иконки, базы и код без разрешения. Для `authorized` вклада нужна ссылка
на разрешение. Сохраняйте notices и attribution.

GPL/AGPL и другие copyleft-компоненты требуют отдельной проверки условий
распространения/сервиса и совместимости; не перелицензируйте их в MIT и не считайте
source-available автоматически open source. Даже permissive-код может содержать
отдельно лицензированные game data. Сомнительный вклад остаётся draft до решения
maintainer/правообладателя; валидатор не выдаёт юридического заключения.

## Проверки

```sh
python -m knowledge.profiles knowledge/game_profiles.json
python -m knowledge knowledge/catalog.json
python -m unittest discover -s tests -v
python -m compileall -q knowledge
```

Нужны отрицательные тесты: неподдерживаемая schema/build/format version,
несуществующее capability, отсутствие evidence, unknown fields, дубли AppID,
неизвестный флаг, draft hint и невозможность включения парсера из профиля.
Генерируйте JSON Schema из Pydantic моделей после изменения контракта.

## Минимальный PR checklist

- [ ] AppID и точный scope версий; unknown явно сохранён.
- [ ] Original/authorized contribution, provenance и отдельная лицензия данных.
- [ ] Source review + synthetic tests + разрешённый приватный отчёт (без save bytes).
- [ ] Нет новых сетевых запросов, команды запуска, private-access grants.
- [ ] Spoiler-safe projection проверена отдельно от публичной базы.
- [ ] Тесты запущены; реальные end-to-end проверки не подменены моками.
- [ ] Review завершён до `approved`; публикация/распространение разрешены отдельно.
