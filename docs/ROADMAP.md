## Продуктовая цель и неизменные границы

Ближайший UX-приоритет — **телефон: Steam → игра → помощник**, без обязательного
Deck/Desktop Mode. Ручная беседа доступна без connector, но не получает аккаунтные
данные автоматически. Базовая цель фонового режима — **без установки**: разрешённый cloud source → подтверждённое
изменение → безопасная проекция → отдельно разрешённая доставка/помощник.
Источник, scheduler и native assistant turn ещё не подтверждены. Steam OpenID
не даёт Cloud-доступа. Ручной browser import — полезный fallback, не автоматический
Cloud. Более быстрый PC/Deck watcher — необязательный отдельный путь.

Регистрация AppID, разрешение источника, распознавание формата, игровая семантика
и доставка — разные gates. Каталог discovery содержит 17 игр, declarative profiles
3, реальных knowledge facts 0: это не 17 парсеров и не owned Steam library.
AppID до 2147483647, owner catalog до 100; all-current не включает будущие игры.
Добавление/выбор не выдаёт grants. Community profile не исполняет код.

Belmont JSON 1.1.3: current health/mana — не максимумы, fragment counters — не
доказанные улучшения. Ни metadata, ни отсутствие достижения не доказывают прогресс.
ER signature не подтверждает версию, слоты или inventory; пустая W3 Cloud-таблица
не доказывает отсутствие сейвов/прогресса. Unknown не превращается в false.

## Ближайшая очередь: результат, evidence, blockers

1. **PHONE — первая беседа только на телефоне.** Steam → выбрать игру → помощник;
   ни Steam Deck, ни Desktop Mode, ни установка не обязательны. На реальном
   телефоне проверить первый визит, login/cancel/retry, выбор, начальное сообщение,
   копирование/ручной ввод, AI link, Back/Forward и повторные нажатия. **Готово:**
   пользователь начинает беседу о выбранной игре/цели без локального агента;
   без connector модель получает только явно сообщённое игроком, а UI не
   утверждает подключение, автоматическую передачу данных или известный прогресс.
2. **CONTEXT — права и свежесть.** Проверить выбор ≠ grant, grant ≠ refresh;
   optional library scope не включается молча. `phone_context` выдаёт только
   текущую разрешённую projection, unknown/disabled/unavailable/expired отдельно.
   Receipt time — время получения, не время сейва или текущая позиция игрока.
   **Готово:** revoke/expiry/пустой ответ/cross-owner тесты и реальный UI не
   превращают отсутствие источника в нулевой прогресс; беседа всё равно возможна.
3. **STEAM — настоящий разрешённый read.** С корректно разрешённой операторской
   настройкой проверить explicit refresh library/achievement источника на
   доступном профиле, private/unavailable ответ и отсутствие hidden-achievement
   утечки. **Готово:** наблюдаемый live response → bounded cache → разрешённое
   отображение с timestamp. MockTransport не закрывает gate; ключ не обходит privacy.
4. **MCP — реальный клиент.** На поддерживаемом account/client проверить
   discovery, OAuth consent/cancel, PKCE, read tools, refresh/revoke; сравнить
   разрешённые факты и freshness с сайтом. **Готово:** реальный tool call с
   account-scoped данными, не просто открытая ссылка или вставленный URL.
   Ручная беседа и MCP с авторизацией — два разных уровня приёмки.
5. **REL/DIAG — интеграция и ограниченная диагностика.** Объединённые 25 файлов
   прошли общий локальный прогон; синтетические браузерные сценарии пройдены.
   Далее проверить настоящий PostgreSQL на той же ревизии. Preview/download должен
   остаться локальным, session-gated, без report POST/storage/automatic submission;
   request IDs не содержат credentials/личные данные. После разрешённого выпуска
   проверить CI/deploy/smoke. Незавершённый QA не маркировать как готовность.
6. **BEL — доказанная семантика отдельно.** Контролируемая before/after пара,
   точная сборка и независимое наблюдение в игре → проверенное сопоставление. Пять
   shapes и raw scalar поля не доказывают предметы/максимумы/прохождение.
7. **ER/W3 И БАЗА ЗНАНИЙ.** Для Elden Ring нужны проверенные лицензии зависимостей,
   точная версия/platform/DLC и семантические fixtures: распознавание сигнатуры не
   gameplay parser. Для Witcher 3 нужны разрешённый образец, версия и проверенный
   read-only decoder. Реальные записи сообщества требуют источников, прав на
   данные, отдельной лицензии, независимого review и spoiler-safe условия показа.
   Декларативный профиль не запускает код и не подтверждает игровой факт.
8. **OPTIONAL DECK / CLOUD.** Проверка физического Deck остаётся отдельным путём,
   не prerequisite PHONE. Автоматический no-install Cloud требует разрешённого
   источника, scheduler и доставки; обычный Steam login их не создаёт.
9. **PUBLICATION CHANNELS.** Каталоги/заявки в каталоги ждут данные издателя,
   адрес поддержки, окончательную privacy/retention политику и реальную acceptance.
   Техническая data-handling страница не заменяет политику. Заявки не отправлены.

## Продолжение после релиза и stop flags

После подтверждённого выпуска брать первый незаблокированный срез, а не ждать
всех внешних интеграций. Не создавать ключи, grants, платные ресурсы или новые
callbacks ради закрытия checklist. Не публиковать private saves, IDs, paths или
секреты; не запускать write/repair над оригиналами. При неизвестной лицензии,
новой стоимости/доступе или отсутствии semantic evidence остановить только
зависимую часть и явно записать необходимое действие/разрешение.
