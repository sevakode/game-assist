# Game Assist: целевая архитектура

Статус: проект решения, 31 октября 2026. Это **не описание готового публичного сервиса**. Архитектурные решения ниже — предложение реализации; внешние требования проверены по официальным источникам в конце разделов.

## 1. Граница текущей beta и цели

Текущая локальная beta: FastAPI/SQLite, один пользователь, Linux watcher метаданных, ручная синхронизация достижений, локальный JSON-only MCP subset. README фиксирует 45 пройденных тестов; это не проверка будущей многопользовательской архитектуры. Нет проверенного декодера сейвов, production OAuth, публичного размещения или Steam/ChatGPT end-to-end. Не публиковать текущий сервер напрямую.

Цель: open source (код под MIT, коммерческое использование допускается); ChatGPT — главный интерфейс; сайт — вход, согласия и личный прогресс; общий публичный MCP без серверного LLM; локальный разбор и хранение, самостоятельный хостинг. Первая тройка: Castlevania: Belmont’s Curse, Elden Ring, The Witcher 3. Цель игрового покрытия — все достижения выбранного издания плюс важные пропускаемые предметы/события, **не обещание уже полного покрытия**.

## 2. Три режима, а не двусмысленное «всё локально»

| Режим | Где личные данные | Что работает удалённо |
|---|---|---|
| Hosted, явный opt-in | Сейвы и полный журнал локально; разрешённая минимальная проекция фактов на общем сервере | Сайт/ChatGPT читают последнюю синхронизацию, даже когда ПК выключен |
| Self-host | Та же схема на сервере владельца; локальный агент подключается только к нему | Зависит от доступности и выбранного подключения |
| Local-only | Локальная БД и интерфейс; никакой загрузки прогресса оператору | Общий сайт не показывает личный прогресс; нет обещания удалённого доступа офлайн |

Согласие на подключение ChatGPT отдельно от локального чтения: факты в ответах MCP покидают устройство и попадают в облачный клиент. Self-host и шифрование на диске не делают такой разговор полностью локальным. Удаление у нас не удаляет ранее отправленные сообщения в ChatGPT. Полностью локальный режим без передачи фактов предполагает локальный интерфейс/совместимый локальный клиент.

ChatGPT не обращается к произвольному localhost напрямую. Официальная справка описывает Secure MCP Tunnel для поддерживаемых продуктов; совместимость конкретного аккаунта и способа установки необходимо проверить отдельно. Не делать туннель обязательным компонентом первой версии и не заменять его случайным публичным туннелем. [OpenAI: local MCP](https://help.openai.com/en/articles/12584461-developer-mode-and-full-mcp-connectors-in-chatgpt)

## 3. Поток данных и модули

```text
разрешённые файлы → стабильный read-only снимок → проверенный parser
  → локальные evidence + progress DB → consent + minimization → delta outbox
                                                        ↓ HTTPS
Steam adapter → evidence store → projection/rules → spoiler gate → MCP → ChatGPT
                                      └──────────→ spoiler gate → Web API → сайт
проверенные игровые пакеты ────────────↑
```

Один общий пакет доменной логики используется локально и на сервере: схема доказательств, правила прогресса, spoiler gate. Отдельные адаптеры транспорта/хранилища. Предлагаемые границы: `core/evidence`, `core/projection`, `core/spoilers`, `profiles`, `agent/outbox`, `server/identity`, `server/sync`, `server/jobs`. Это новые целевые модули, не существующие возможности.

- Агент видит только подтверждённые пользователем пути; не меняет сейвы. Разбор в ограниченном процессе: лимиты CPU/памяти/размера, без сети, только копия снимка. Версия игры/формат не поддержаны → `unsupported`, не угаданный прогресс.
- В исходящей схеме allowlist: `event_id`, `device_id`, `sequence`, `appid`, `playthrough_id`, `fact_key`, типизированное значение, источник, версия parser, время наблюдения, `consent_epoch`. Пользователь определяется credential, не полем тела запроса.
- Не передавать по умолчанию содержимое/пути/имена файлов, локальное имя пользователя, полный хеш сейва, тексты заметок. Даже производные факты требуют preview и разрешения на синхронизацию. Идентификаторы потенциально раскрывают сюжет и также фильтруются перед MCP.
- Evidence хранит `verified / user_confirmed / inferred / unknown`, происхождение и время. Подтверждение достижения подтверждает достижение, но не весь текущий сейв. Достижения относятся к аккаунту; квесты/предметы — к конкретному прохождению. Роллбэк сейва не должен «откатывать» достижения аккаунта.
- Конфликтующие источники сохраняются, показывают неопределённость и не запускают необратимые рекомендации. Отсутствие достижения не доказывает отсутствие предмета/пройденного босса.

## 4. Идентификация и авторизация

Разделить четыре доверительные границы: web session, ChatGPT OAuth grant, pairing агента, Steam link. Внутренний `user_id` не равен SteamID; SteamID хранить только в таблице связи. Из авторизации ChatGPT нельзя получить разрешение на чтение новых файлов.

Публичный MCP — OAuth 2.1 resource server: HTTPS, protected-resource metadata, discovery authorization server, authorization-code + PKCE S256, `resource` в запросах и строгая проверка audience. На каждом запросе проверять подпись/issuer/expiry/scopes; чужие токены не принимать и не пересылать в Steam. Client registration согласовать с клиентом: предпочтительно поддерживаемый CIMD; DCR/предрегистрация — при необходимости. [MCP authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization), [OpenAI authentication](https://developers.openai.com/plugins/build/auth)

Практические решения проекта:

- Не писать криптографию/authorization server с нуля; выбрать проверенную реализацию после отдельного решения о хостинге. Короткоживущий access token, ротация refresh, отзыв, точные redirect allowlists, одноразовые state/code, безопасное получение metadata. Проверить совместимость реальным ChatGPT flow до публикации.
- OAuth scopes задают операции (`progress.read`, `achievements.read`, `hints.read`); таблица `game_grants(user_id, appid, capability, consent_epoch)` ограничивает игры и источники. Эффективное право = token scope ∩ актуальное согласие ∩ доступ к конкретной игре. Проверка в API, MCP, worker и загрузке delta.
- Вход на сайте — защищённая серверная сессия с HttpOnly/Secure/SameSite cookie и CSRF-защитой. Изменение согласий и spoiler policy — только подтверждённое действие пользователя на сайте; read-only MCP не расширяет разрешения по просьбе модели.
- Агент получает отдельную ограниченную credential через короткоживущий одноразовый pairing code, подтверждённый в уже авторизованном браузере. Хранение в системном credential store, отзыв устройства, минимальный scope ingestion; не web cookie и не общий SGC_TOKEN.
- Steam OpenID подтверждает SteamID, а не доступ к приватным данным. Steam partner OAuth требует отдельного взаимодействия с Valve; не считать его доступным обычному проекту. Пароли/cookies Steam не запрашивать. [Steam OpenID](https://partner.steamgames.com/doc/features/auth), [Steam OAuth](https://partner.steamgames.com/doc/webapi_overview/oauth)

## 5. Изоляция и удаление

Hosted: PostgreSQL, все личные строки содержат `user_id`; составные foreign keys/unique constraints не допускают связи между владельцами. Запросы выполняются в tenant context, дополнительно RLS и отдельные роли приложения/миграций. Публичный каталог игровых знаний физически/логически отделён от личных evidence. SQLite остаётся локальной реализацией.

Private cache key обязательно включает пользователя, игру, прохождение, revision, policy version и consent epoch. Нельзя кэшировать персональные ответы только по AppID. Сессия MCP не является идентификатором владельца. Worker повторно проверяет grant перед выполнением, не доверяет старому payload задания.

Отзыв немедленно запрещает выдачу и новую синхронизацию, отменяет задания, инвалидирует cache. Delete удаляет проекции/evidence, токены устройств и ожидающие события; обработка резервных копий — с опубликованным сроком хранения и защитой от восстановления удалённой записи. Возвращённый после долгого офлайна агент не может загрузить удалённые данные со старым consent epoch. Экспорт и удаление только в пределах текущего владельца. Логи: без токенов, сырого прогресса, файловых путей и содержимого; короткий технический audit с настраиваемым retention.

## 6. Строгий режим без спойлеров: до модели

Инструкция модели «не спойлери» недостаточна. Игровой пакет содержит проверенные условия раскрытия отдельно от полного справочника. `known` определяется положительным доказательством/явным подтверждением игрока, не догадкой по времени игры. `unknown` и неподтверждённая версия пакета → fail closed.

Обязательная последовательность для **всех** чтений:

1. Проверка владельца/игры/источника.
2. Выбор текущего прохождения и подтверждённых известных сущностей.
3. Детерминированный rule engine выбирает допустимый следующий шаг и нейтральный текст.
4. Spoiler gate строит отдельный allowlisted DTO; сырые объекты нельзя сериализовать.
5. Проверка DTO, затем MCP/Web serialization.

Фильтровать не только названия боссов: описания/иконки секретных достижений, ключи объектов, URL/slugs и заголовки источников, координаты/подписи карт, counts неизвестного контента, причины ошибок, structuredContent, resources, UI metadata, tool descriptions. Не отправлять браузеру скрытое содержимое для последующего CSS-размытия. Не предоставлять generic raw-search/fetch, обходящий gate.

Первый режим: `strict`. Пользователь разрешил нейтральное «не забудь осмотреться» перед необратимым действием, без объяснения будущих последствий. Пример допустимого предупреждения — «Перед продолжением стоит ещё проверить уже знакомую область» **только если есть безопасное подтверждённое правило**; иначе «Недостаточно сведений, чтобы проверить пропускаемые цели». Во всех режимах помощи будущие сюжетные детали остаются скрыты: можно увеличивать подробность только уже известного игроку контекста. Отключение защиты от будущих спойлеров не входит в утверждённые требования; модель не может повысить уровень раскрытия. Разблокированное достижение не автоматически разрешает все связанные сюжетные детали.

Гарантия ограничена выводом нашего MCP/сайта: ChatGPT уже может знать сюжет из других источников, а ранее раскрытый текст нельзя отозвать из истории. В строгом режиме выдавать короткие готовые проверенные подсказки, а не полный справочник для свободного пересказа. Инструкции клиента требуют использовать только эти подсказки, не дополнять их знаниями о сюжете и отказываться от конкретики при неизвестном состоянии. Это снижение риска, не математическая гарантия поведения внешней модели. Приёмочные adversarial tests проверяют запросы «игнорируй ограничения», подбор неизвестных ID, чужие прохождения, секретные достижения, URL/metadata, неоднозначные наблюдения и ранее раскрытые факты. Публично обещать абсолютную защиту от спойлеров нельзя.

## 7. Стоимость: работа по изменениям, без серверного LLM

Начать с одного приложения и небольшой БД; persistent jobs в БД вместо обязательного Redis/отдельной очереди. Добавлять инфраструктуру по измеренным узким местам, а не заранее. Это уточняет более тяжёлый вариант Platform в PRODUCT.md.

- Save watcher: debounce стабильной записи, локальная дедупликация, разбор только изменившихся снимков. В сеть — компактные пачки deltas, не heartbeat с полным состоянием.
- Outbox: уникальность `(device_id, event_id)`, последовательность/ack cursor, retries с backoff+jitter. Повторное событие идемпотентно. Разрыв/неподдерживаемый порядок → resync минимальной разрешённой проекции; это не загрузка сейва.
- Steam jobs: ручной refresh плюс адаптивный интервал только для активных согласованных игр; offline/неактивные — реже/пауза. Single-flight по пользователю и игре, budget запросов, backoff при ошибках/ограничениях; private/error ≠ нулевой прогресс.
- Каталог достижений кэшировать отдельно по игре/языку/версии, личные unlocks — по пользователю. Valve документирует отдельные методы списка достижений пользователя и схемы игры. [ISteamUserStats](https://partner.steamgames.com/doc/webapi/ISteamUserStats)
- Проекцию пересчитывать только при изменении фактов, согласий, spoiler policy или версии игрового пакета. MCP читает готовый snapshot и freshness timestamp; не запускает сканирование библиотеки или внешний поиск на каждый вопрос.
- Ограничения размера, pagination, per-user/device quotas, admission control и kill switch для внешних fetch. Собирать запросы/активного пользователя, размер БД, очередь, egress, latency; выставить операционный лимит после выбора бюджета.

«Почти бесплатно» — цель, не гарантия. Остаются hosting/storage/backups/traffic/auth/domain и сопровождение. Не требуется оплачиваемый LLM API на сервере; доступ к ChatGPT и правила его подключения — отдельная сторона. Провайдеры/тарифы здесь намеренно не выбраны.

## 8. Игровые пакеты и этапы

Три независимых слоя данных: **community world knowledge** — проверенные общие факты об игре; **versioned save mapping** — подтверждённое соответствие конкретных полей формата сейва игровым фактам для конкретной версии; **personal tri-state** — личное состояние `получено / не получено / неизвестно` с доказательством. Наличие объекта в общем справочнике не подтверждает ни поддержку его чтения из сейва, ни состояние игрока. `Не получено` требует положительного доказательства отсутствия в поддерживаемом источнике, а не просто отсутствующего достижения.

Первый конкретный сценарий — улучшения HP/маны в Belmont’s Curse: отдельно вести известные миру улучшения, проверенные mappings и личные три состояния; без проверенного mapping использовать явное подтверждение игрока или `неизвестно`. В строгом ответе показывать только безопасные подсказки в уже известном контексте, не местонахождение будущих улучшений. Правила community-данных и проверки источников описаны отдельно в [COMMUNITY_DATA.md](COMMUNITY_DATA.md).

Пакет: game/edition/DLC/build, проверенные achievement identifiers, важные missables, условия/сроки, prerequisites, безопасные подсказки, provenance/license, coverage status, тесты spoiler gate. Код open source не даёт права копировать чужие карты/тексты. Полное покрытие и совместимость с новой версией проверяются отдельно.

Для всех трёх игр начать с достижений и ручных подтверждений; не объявлять decoder без реальных разрешённых fixtures и тестов. Belmont’s Curse особенно остаётся неподтверждённым профилем, пока нет проверяемого формата/контента. Не выводить квесты и предметы из одной даты изменения сейва. Порядок реализации по готовности доказательств, а не выдуманной поддержке.

| Этап | Результат и критерий выхода |
|---|---|
| A. Локальный контракт | Версионированные evidence/проходжения, consent epochs, строгий DTO и тесты утечки; прежние тесты остаются зелёными |
| B. Полезный локальный продукт | Три честно размеченных пакета с coverage matrix, безопасный трекер достижений/подтверждений; ручной режим полезен без parser |
| C. Sync и multi-user | Минимальные deltas, pairing, tenant isolation; тесты A→B недоступности, replay, офлайн revoke/delete, cache separation |
| D. Публичный MCP + сайт | OAuth/PKCE/resource, read-only tools, общий безопасный DTO; успешный реальный вход и E2E с двумя тестовыми пользователями в ChatGPT |
| E. Поддерживаемые parsers и выпуск | По одному формату/версии с fixtures, отрицательными тестами и OS-проверками; self-host packaging, security review, restore/delete drill, опубликованные лимиты |

Public launch — только после D и операционной проверки. Установщики/автообновления требуют отдельной проверки подписи и цепочки поставки. Текущая реализация остаётся локальной. Следующий публичный этап проектируется поверх повторно используемого, поддерживаемого OAuth-стека, а не самописной авторизации. Никакой этап сам по себе не разрешает push, публикацию, расходы, создание аккаунтов или ключей.

## 9. Нерешённые пользовательские решения

1. MIT для кода уже выбрана (см. LICENSE); остаются отдельные права/лицензии на игровые данные и карты.
2. ОС первого выпуска и точные издания/DLC трёх игр.
3. Какой режим onboarding основной: hosted минимальные факты или local-only; какие факты разрешено хранить удалённо и сколько.
4. Что считать «важными предметами»: минимум всё achievement-critical + необратимо пропускаемое; расширение на build-specific/коллекционное требует выбора.
5. Нейтральные предупреждения перед необратимыми действиями уже разрешены; последствия и неизвестные названия скрыты. Отдельно решить показ общего числа достижений; до ответа скрывать неоднозначное.
6. Месячный предел расходов/ожидаемое число активных пользователей и способ доступа к ChatGPT. До выбора — никаких тарифных обещаний и развёртывания.
