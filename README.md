# Game Assist — локальная beta 0.2

Локальная однопользовательская основа Steam-компаньона. Это **не готовый облачный сервис, не установленный плагин ChatGPT и не универсальный декодер сейвов**. Согласованные требования — в docs/REQUIREMENTS.md; лицензия MIT.

## Реализовано

- Структурный read-only reader Belmont JSON 1.1.3: четыре поля ресурсов/счётчиков, проверка структуры и приватное сравнение снимков. Это НЕ определение взятых улучшений или их мест.

- Строгая проекция без закрытых достижений/внутренних ID/скрытых totals и имён сейвов; три уровня помощи не отключают фильтр.
- Нейтральные напоминания разрешены, но без проверенного игрового триггера не выдаются.
- Версионированная схема общественной базы, валидатор, tri-state resolver и безопасные подсказки. Каталог пока пустой; нет придуманных реальных находок.
- Дедупликация наблюдений, максимум 10 снимков на игру/тип/источник, лимит входящего тела 2 MiB.

- FastAPI + SQLite, отдельные разрешения для каждой игры, по умолчанию доступ запрещён.
- Русский веб-интерфейс: подключение, игры, разрешения, наблюдения, экспорт, удаление данных.
- Steam OpenID: проверка ответа непосредственно у Steam, одноразовое состояние и привязка к браузеру. Реальный вход ещё не проверен.
- Получение достижений одной разрешённой игры через Steam Web API, когда оператор настроил доступ. Ошибки доступа не превращаются в нулевой прогресс.
- Linux-монитор выбранных файлов: стабильные снимки, ограничение чтения, отказ на ссылках/небезопасных путях, передача только метаданных на loopback. Сейвы не изменяет.
- Локальный MCP JSON HTTP: list_games, get_achievements, get_save_status, get_progress, suggest_next_step. Только чтение и проверка разрешений.
- Проверяемое происхождение наблюдений. Метаданные сейва не считаются пройденными боссами/квестами.

## Запуск

Python 3.11+; проверено на Python 3.12/Linux.

```sh
python -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
export SGC_TOKEN="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
python -m server
```

Откройте http://127.0.0.1:8000 на этом же компьютере. Введите установленный вами SGC_TOKEN в поле подключения. Не отправляйте его в чат, не сохраняйте в репозитории. Интерфейс хранит токен только в памяти страницы: после перезагрузки введите заново.

Добавьте игру и явно сохраните разрешения. Для наблюдения файлов включите `saves.metadata`, затем во втором терминале с тем же SGC_TOKEN:

```sh
python agent/watch.py --appid 4231820 --path /absolute/path/to/selected/save-directory --interval 60
```

Однократная проверка: добавьте `--once`. Watcher ждёт два совпадающих снимка. При ошибке чтения старые серверные сведения сохраняются; пустой успешный снимок отличается от ошибки. Ограничения: 64 MiB/файл, 256 MiB/снимок, 4096 файлов, 16384 записей, глубина 64.

## Steam

Кнопка входа ведёт на официальный Steam. Пароль Steam приложение не принимает. Сам вход не открывает приватную библиотеку или облачные сейвы.

Для запросов достижений оператору нужен разрешённый Valve Web API доступ, настроенный через `SGC_STEAM_API_KEY` в окружении сервера. Ключ не вводится пользователем в интерфейсе и не передаётся в URL. Ключ не создавался. Встроенный OpenID/API flow приложения проверен моками, не реальным входом. Отдельный диагностический вход владельца в официальный Steam Cloud и чтение разрешённой копии сейва выполнены; это не проверка интеграции приложения. Без настройки отображается `not_configured`.

Синхронизация достижений сейчас запускается кнопкой; фонового планировщика достижений ещё нет. При отвязке Steam удаляются связанные Steam-наблюдения. Для сервера используется один процесс: состояние входа/защита от повторов находятся в памяти.

## Локальный MCP

POST http://127.0.0.1:8000/mcp с `Authorization: Bearer ...`, `Content-Type: application/json`, `Accept: application/json, text/event-stream`.

Версия протокола 2025-03-26, stateless JSON-only subset. GET возвращает 405 (SSE отсутствует). Это локальный интерфейс для совместимого клиента, **не подключение облачного ChatGPT к localhost**. Для публичного подключения потребуются отдельные HTTPS-хостинг, OAuth, изоляция пользователей и проверка в ChatGPT. Не открывайте этот сервер в Интернет и не используйте случайный туннель.

## Честные ограничения

- Windows watcher пока намеренно отказывается работать: безопасный нативный обход файлов ещё не реализован и не проверен. SteamOS отдельно не тестировался.
- Нет установщиков, автозапуска, трея, подписанных обновлений и фоновой синхронизации Steam.
- Reader Belmont проверяет наблюдавшуюся структуру 1.1.3, но семантика счётчиков/объектов и места HP/маны не доказаны. Профили и публичные тесты не содержат личных сейвов.
- Нет автоматического импорта библиотеки/all-games, облачного MCP OAuth, многопользовательского хранения и законченного игрового советчика/карт.
- SQLite содержит локальные метаданные без шифрования; защищайте саму учётную запись ОС. Это dev/beta, не независимый аудит безопасности.
- Удаление в UI касается данных компаньона, а не оригинальных сейвов.

`docs/PRODUCT.md` — целевой дизайн, а не перечень уже реализованного. Архивы-источники сохранены отдельно. Задания для агентов в поставку не включены. Ничего не опубликовано и не отправлено в GitHub.

## Структурное исследование Belmont

```sh
python -m decoders.belmont /private/copied-save.sav
python -m decoders.belmont /private/before.sav --compare /private/after.sav
```

CLI выводит только разрешённую сводку или признак изменения. `private_diff` содержит непрозрачные идентификаторы, предназначен лишь для локального исследования и не подключён к MCP. Сейвы хранить за пределами проекта/публикуемого архива. Поддержка чтения путей проверена на Linux, не Windows; использовать стабильные приватные каталоги. Поля currentHealth/currentMana не являются максимумами; fragmentCount пока не интерпретирован как число улучшений.

## Опциональная сводка ресурсов в API/UI

Включите отдельно `saves.summary` для Belmont. Это не включает `saves.metadata`. Затем:

```sh
python agent/watch.py --appid 4231820 --path /private/copied-save.sav --decode-belmont --interval 60
```

Этот режим отправляет только четыре сырых поля и ограничения интерпретации, не метаданные файлов/ID объектов/содержимое сейва. По умолчанию декодирование выключено. Режим без `--decode-belmont` остаётся metadata-only. `GET /v1/games/4231820/save-summary` и MCP `get_save_summary` проверяют отдельное согласие; отзыв немедленно закрывает данные. Сервер считает сведения сообщёнными локальным парсером, а не независимым доказательством предметов. Проверен реальный локальный HTTP-путь на синтетическом сейве, исходные байты и mtime не изменились.

## Кандидат удалённого сервиса и Steam Deck

`remote_server/` — отдельный ещё не размещённый сервер с official MCP SDK 1.29 OAuth/PKCE, Steam OpenID, аккаунтами, явной привязкой устройства и tenant-scoped сводками. Требуется HTTPS и постоянное хранилище; старый local server нельзя открывать в Интернет. См. remote_server/README.md и docs/END_TO_END_ACCEPTANCE.md.

`deck/` — stdlib-only пользовательский клиент/установщик: опциональный ограниченный поиск известного сейва, подтверждение пути, привязка через телефон, приватная credential и ограниченная offline-очередь. См. docs/STEAM_DECK.md. Установка на настоящем Deck и переключение Game Mode НЕ проверены. В текущем кандидате credential устройства истекает через 30 дней: автоматического продления устройства ещё нет.

```sh
python -m pip install -r requirements.txt -r remote_server/requirements.txt
python3 -m deck setup --server https://YOUR-DEPLOYED-SERVICE.example
```

Последняя команда — пример для будущего реального HTTPS-сервиса, не готовая ссылка. Размещение пока не выполнено. Render Free + Neon выбраны владельцем как временный бесплатный путь. PostgreSQL-адаптер проверен на одноразовом локальном PostgreSQL 17.11, включая гонки, отзыв доступа и сохранение состояния. Реальные Neon TLS/pooling, Render и мобильное подключение ещё не проверены; размещение на ephemeral SQLite запрещено. CI-конфигурация добавлена в исходники, GitHub Actions ещё не запускались.

## Проверка PostgreSQL и пакет для Deck

`remote_server/test_postgres.sh` запускает и удаляет одноразовый локальный PostgreSQL; требует PG_BINDIR/PG_SHAREDIR. В полном прогоне прошли 188 тестов без пропусков, включая 29 PostgreSQL-тестов. Без GA_TEST_POSTGRES_URL соответствующие тесты намеренно пропускаются, и такой прогон не является проверкой Postgres. CI настроен на отдельный тестовый postgres:17, но удалённый GitHub workflow ещё не запускался.

`python tools/package_deck.py` собирает детерминированный клиентский архив только из разрешённых файлов кода. Будущий `/setup` на размещённом сервисе покажет ссылку на этот архив и SHA-256. Архив не содержит сейвов, конфигурации аккаунта или токенов. Это не уже опубликованный адрес и не доказательство установки на Deck.
