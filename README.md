# Game Assist

Open-source игровой компаньон с защитой от спойлеров. Основной интерфейс — совместимый AI-клиент, а выбранный локальный сейв читает небольшой компаньон на устройстве игрока.

**MIT · экспериментальная beta · исходные сейвы только для чтения**

- Сайт: https://game-assist.onrender.com/
- Настройка Steam Deck: https://game-assist.onrender.com/setup
- Remote MCP: https://game-assist.onrender.com/mcp
- Проверки: https://github.com/sevakode/game-assist/actions

## Статус

Размещён отдельный HTTPS-сервис на Render Free с постоянной PostgreSQL-базой Neon. Проверены запуск, health endpoint, OAuth metadata, отказ неавторизованному MCP и контрольная сумма клиентского ZIP. **Реальный вход с телефона, подключение Claude и работа на физическом Steam Deck ещё требуют приёмки.** Это не заявление о готовности всех продуктовых требований.

Последний полный локальный прогон: **197 тестов**, включая реальный одноразовый PostgreSQL 17.11; отдельно проверяются JS/UI и каталог знаний. GitHub CI выполняет проверки на PostgreSQL. Внешний Steam в автоматических тестах заменён моками; настоящий диагностический вход в Steam Cloud не равен проверке OpenID нашего приложения.

Текущий удалённый сервис передаёт только согласованную структурную сводку Belmont’s Curse 1.1.3. Он **не определяет местоположения всех улучшений, не расшифровывает всех боссов/квесты и не гарантирует все достижения**. Целевые игры: Belmont’s Curse, Elden Ring, The Witcher 3; объём фактической поддержки указан ниже и в документации.

## Как устроена связь

Steam Deck → HTTPS-сервис ← AI-клиент на телефоне.

Deck не нужен публичный IP или входящие порты. После явного выбора файла и подтверждения привязки он отправляет только разрешённую сводку. Сырой сейв на сервер не загружается. Общий сервер и собственная установка — разные варианты размещения.

Первый мобильный клиент для приёмки — Claude с удалённым MCP. Подключение обычно настраивается через веб-интерфейс Claude. Поддержка собственного MCP в нативном мобильном ChatGPT не заявляется; актуальные ограничения и критерии см. [END_TO_END_ACCEPTANCE](docs/END_TO_END_ACCEPTANCE.md).

## Что реализовано

- `server/`: однопользовательский локальный FastAPI/SQLite API, интерфейс, явные разрешения по играм, экспорт/удаление, read-only MCP.
- `remote_server/`: official MCP SDK 1.29, OAuth authorization-code + S256 PKCE, точные callback allowlists, rotation/revocation, Steam OpenID, изоляция аккаунтов, привязка устройства, SQLite или PostgreSQL.
- `deck/`: Linux-клиент со стандартной библиотекой, пользовательский установщик, явное согласование папки/привязки, приватная credential, ограниченная очередь и backoff.
- `agent/watch.py`: ограниченный read-only watcher. Стабильные снимки, безопасный обход, дедупликация, отказ на неподдерживаемых или меняющихся данных.
- `decoders/belmont.py`: структурное чтение JSON 1.1.3 и приватное сравнение снимков. Только четыре сырых поля ресурсов/счётчиков; семантика предметов не доказана.
- `knowledge/`: версия схемы, валидатор, три состояния «взято / не взято / неизвестно» и проверенные нейтральные подсказки. Реальный каталог пока пустой; тестовые примеры синтетические.

### Без спойлеров

Фильтрация выполняется до выдачи в MCP/сайт. Закрытые достижения, внутренние ID, скрытые знаменатели и имена сейвов не раскрываются. Режимы `minimal`, `standard`, `guided` меняют помощь, а не разрешение на будущие спойлеры.

Нейтральное «не забудь осмотреться» разрешено только при проверенном игровом условии. Пока такого правила нет, сервис не выдумывает предупреждение. Внешняя модель может знать сюжет независимо от MCP — абсолютная гарантия её поведения невозможна.

### Точность данных

`currentHealth` и `currentMana` — текущие значения, не максимумы. `healthUpgradeFragmentCount` и `manaUpgradeFragmentCount` пока не трактуются как количество полученных улучшений. Метаданные файла не доказывают прохождение, а отсутствие достижения не доказывает пропущенный предмет. Неподдерживаемая версия или отсутствующее доказательство означают «неизвестно».

## Локальный запуск

Python 3.11+; тестирование сервера выполнено на Python 3.12/Linux.

```sh
python -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
export SGC_TOKEN="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
python -m server
```

Откройте http://127.0.0.1:8000 на том же компьютере. Установленный вами локальный токен вводится только в локальном интерфейсе; не отправляйте его в чат и не сохраняйте в репозитории. Он хранится в памяти страницы. Этот ручной режим — инструмент разработки, не финальное мобильное подключение.

Для метаданных включите `saves.metadata`, затем с тем же токеном:

```sh
python agent/watch.py --appid 4231820 --path /absolute/selected/save-directory --interval 60
```

Для структурной сводки включите отдельно `saves.summary` и выберите **один файл**:

```sh
python agent/watch.py --appid 4231820 --path /private/copied-save.sav --decode-belmont --interval 60
```

Этот режим отправляет только сводку; он не требует `saves.metadata`. Добавление `--once` выполняет два стабильных измерения и завершает работу. При ошибке прежняя серверная сводка не стирается.

Самостоятельное структурное исследование копий:

```sh
python -m decoders.belmont /private/copied-save.sav
python -m decoders.belmont /private/before.sav --compare /private/after.sav
```

`private_diff` — только для локального исследования; непрозрачные идентификаторы из него не выдаются через MCP. Сейвы храните вне репозитория.

## Steam Deck и удалённый сервис

См. [инструкцию Deck](docs/STEAM_DECK.md) и [инструкцию сервера](remote_server/README.md). Установка пользовательская, без sudo, изменения read-only SteamOS или загрузки стороннего runtime. Требуются Python с `venv` и работающий `systemctl --user`. Реальное оборудование ещё не проверено.

```sh
python3 -m deck setup --server https://game-assist.onrender.com
```

Опциональный поиск предлагает только существующий файл в ограниченном известном Proton-пути для AppID 4231820; путь и привязку нужно подтвердить. Это CLI-onboarding, не законченный графический установщик. Credential устройства пока истекает через 30 дней и требует повторной привязки.

Вход Steam подтверждает SteamID, но не открывает приватные данные или произвольные облачные сейвы. Для локальной функции достижений нужен операторский `SGC_STEAM_API_KEY`; игроки не вводят ключ в интерфейсе. Официальный облачный `read_cloud` требует отдельного доступа Valve. Браузерная сессия не заменяет массовую API-интеграцию.

## Проверки

```sh
python -m pip install -r requirements.txt -r remote_server/requirements.txt
python -m unittest discover -s tests -v
python -m compileall -q server agent knowledge decoders deck remote_server tools
node --check web/app.js
node web/tests/check-ui.cjs
python -m knowledge knowledge/catalog.json
```

Без `GA_TEST_POSTGRES_URL` тесты реального Postgres пропускаются. `remote_server/test_postgres.sh` поднимает и удаляет **одноразовый loopback PostgreSQL** при заданных `PG_BINDIR`/`PG_SHAREDIR`. Никогда не направляйте разрушительные тесты на рабочую базу.

`python tools/package_deck.py` собирает детерминированный ZIP только из разрешённых файлов кода; контрольная сумма публикуется рядом. В архиве нет реальных сейвов, аккаунтных настроек или токенов.

## Ограничения и документы

- Бесплатный Render засыпает; первое обращение может ждать около минуты или получить таймаут. Это временная тестовая инфраструктура, не SLA.
- SQLite нельзя размещать на ephemeral disk. Hosted-режим требует проверенного TLS к постоянной базе; проверка сертификата не отключается.
- Нет проверенной полной базы мира или готовых семантических декодеров трёх игр. Первый приоритет — проверенная привязка HP/маны Belmont.
- Windows watcher намеренно fail-closed, нативная реализация и проверка не завершены.
- Не заявлены прохождение реального phone/Deck OAuth, Game Mode, suspend/resume, финальная юридическая/операционная готовность или независимый аудит безопасности.
- Экспорт/удаление касаются данных компаньона, не оригинальных файлов игры.
